墨舟 0.4.1 代码优化 · 2026-10-28

范围
沿用 0.4 文学书刊界面和小说文件格式。优化输入统计、AI 流式呈现、保存及备份中的重复工作。

实现
1. ManuscriptStatistics 使用条目对象身份及不可变正文引用缓存字数、段落数。只重算改变的正文；章节汇总仍每次遍历当前章节列表，以正确处理新增、删除及分类变化。相同 ID 的小说副本互不串计，ConditionalWeakTable 不阻止已关闭条目回收。
2. AI 回调只追加缓冲区；UI 线程以约 40 毫秒间隔分批追加到文本框。结束、取消及错误路径刷新尾段并解绑定时器；断开和连接失败清理旧客户端与模型控件。
3. 保存前逐字节核对已验证的私有基线后，省去旧稿重复反序列化。模型校验、冲突检查、写入锁、临时文件与备份顺序保持不变。
4. ZIP 备份的历史文件和聊天记录采用 64 KiB CopyTo 缓冲区，避免逐个整文件分配字节数组。主稿仍先完整读取并验证。

验证
.NET SDK 8.0.422，Windows，串行构建；相关构建 0 警告、0 错误。
Core.Tests 28/28，Desktop.Tests 122/122，Bookshelf.Tests 15/15，Codex.Tests 12/12，Graph.Tests 19/19，共 196 项通过。
新增检查包括缓存失效、同 ID 副本隔离、弱引用回收、段落语义、实际 WPF 计数控件、ZIP 原始字节一致性、流式顺序/尾段/并发及清理后的回调抑制。
模拟缓冲检查中，15,000 个短片段按测试设定的刷新频率合并为少于 50 次呈现回调。此项验证批处理行为，不是实际模型吞吐率测量。
协议检查使用受控子进程，没有请求真实模型或使用账号生成额度。首次以 dotnet DLL 启动 runner 导致其自身进程路径指向 dotnet.exe，12 项失败；改用 runner EXE 后 12 项通过，未为此更改产品协议代码。
独立只读代码审查未发现新增实质缺陷；XAML、ProjectContent 计数算法及 CodexClient 与 0.4 源码包一致。

统计微基准
200 章，每章 5,000 个汉字，总计 1,000,000 字；预热后对同一章模拟 100 次编辑，每种实现测 5 轮，比较耗时中位数，逐轮校验统计结果相等。
首次本机测量：旧实现 463.9501 ms，新实现 7.9563 ms（100 次统计合计）。
将同一基准纳入源码包后复测：旧实现 496.1190 ms，新实现 8.5248 ms；统计输出校验一致。
每轮当前线程分配字节：旧实现 1,038,840，新实现 1,025,240，包含构造修改后正文的分配。
仅测统计计算；排除编辑器布局、磁盘保存及 AI，不代表整个软件提速同样比例。不同设备与负载会影响结果。
复现：
  dotnet run --project Mozhou.Benchmarks -c Release -p:BuildInParallel=false
