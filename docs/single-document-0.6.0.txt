墨舟 0.6.0 · 独立小说文档使用说明

本文对应0.6.0，发布与下载状态以仓库Releases为准。

一本小说，一个文档
新建小说保存为一个 .mozhou 文件，包含：
- 全部正文、人设、大纲、世界观、灵感与其他条目资料。
- 人物关系、关系说明和图中布局。
- 已导入的参考图副本。
- 该小说的AI聊天记录。
- 最近30次保存的稿件历史。

.mozhou 使用 Windows 系统提供的 SQLite 作为容器。自动保存直接更新文档；界面显示保存成功后，最新稿件已写入主文件。图片预览使用的临时缓存可以从文档重新生成，不是小说的保存位置。

新建与打开
1. 启动墨舟，在书架选择“新建小说”，填写书名并选择 .mozhou 文件保存位置。
2. 继续写作可直接从书架打开，或使用“打开/导入”选择一个 .mozhou 文件。
3. 旧版小说通过选择 project.mozhou.json 打开；已登记的旧文件夹也可继续从书架使用。

旧小说转换为单文档
1. 先打开旧小说。
2. 在项目菜单选择“另存为墨舟文档…”，为新 .mozhou 文件选择保存位置。
3. 保存成功后，墨舟切换到新文档，后续编辑和自动保存更新新文件。

转换会保留旧文件夹，不覆盖或删除旧稿。生成的新文档包含当前稿件、参考图、聊天和保存历史。新旧两份之后各自保存，编辑其中一份不会同步到另一份。

仍使用旧格式时，请保留整个小说文件夹：project.mozhou.json、assistant-chat.json、assets/images/、project.mozhou.json.bak 和 backups/ 都可能属于这本作品。不要只搬走旧JSON主文件。

移动、复制与重新定位
先等待保存完成并退出墨舟，再复制或移动 .mozhou 文件。正常完成保存后，只移动这一个文档即可携带整本小说，不需要复制程序目录或图片预览缓存。

写入期间，文档旁可能短暂出现同名的 -journal 文件；正常提交后会移除。请在保存完成、应用退出后再搬运文档，避免只复制仍在写入中的主文件。

文档换位置后，原书架记录可能找不到它。可从新位置重新打开，或通过书架的重新定位操作更新位置。书架索引 bookshelf.json 和本机设置 mozhou-settings.json 仍保存在程序目录，它们不属于小说文档；升级程序时可保留以沿用书架和设置。

图片与聊天
导入参考图会保留图片副本，原图随后移动或删除不影响已保存的文档。图库的预览缓存可再生，无须随文档复制。
图片不会自动发送给Codex，也不会嵌入正文TXT/Markdown导出。该小说的AI聊天保存在文档内；使用AI仍需要本机官方Codex、可用的ChatGPT登录和网络。

备份与正文导出
“另存为墨舟文档…”可生成独立的文档副本并切换到副本，原稿保留。
完整ZIP备份导出为旧版逻辑目录结构，包含小说JSON、图片、聊天及保存历史。恢复时将ZIP解压到文件夹，再从墨舟选择其中的 project.mozhou.json 打开；需要单文档时，可再次使用“另存为墨舟文档…”。
ZIP不是 .mozhou 容器，不能仅通过修改扩展名转换。
TXT/Markdown只导出正文，不包含完整设定、图片、关系图或聊天；要保留整本作品，请使用文档副本或完整ZIP备份。

兼容与运行环境
- 运行墨舟0.6.0需要Windows和.NET 8 Desktop Runtime；从源码构建需要.NET 8 SDK。
- Windows便携ZIP必须完整解压运行，同目录的DLL和运行配置需要保留。
- 0.5.0不能打开新的 .mozhou 容器；新文档需要0.6.0或更新的兼容版本。
- 0.6.0继续支持旧版project.mozhou.json文件夹；转换时保留旧稿，方便继续使用原版本。
- 墨舟不会自动注册 .mozhou 的系统文件关联。请从应用内打开，或在Windows“打开方式”中选择Mozhou.exe。
